# Phase 1 Plan 06: Track C Hold-Out Cohort Split Summary

One-liner: Deterministic sha256(seed:episode_id) hold-out split generator with 30% hold-out fraction, producing a 568-row signal-candidate-keyed proxy CSV for Track C (REC-02) per `05-holdout-cohort-design.md` section 3.

## What Shipped

### 1. `scripts/red-team-hybrid/build_holdout_split.py` (235 lines)

Stdlib-only deterministic split generator. Follows `freshness_watchdog.py` style template exactly:

- Shebang + comprehensive docstring citing `05-holdout-cohort-design.md` section 3 verbatim
- `from __future__ import annotations`
- Stdlib imports only: `argparse`, `csv`, `hashlib`, `json`, `sqlite3`, `sys`, `datetime`, `pathlib`, `typing`
- Module-level constants with REC-02 traceability (`DEFAULT_SEED=20260406`, `DEFAULT_HOLDOUT_FRACTION=0.3`, `DEFAULT_OPERATIONAL_COLLECTORS`)
- Pure-function decomposition: `assign_split`, `query_candidates`, `build_split_rows`, `write_csv`, `summarize`
- Read-only sqlite3 via `file:{db_path}?mode=ro` URI
- Argparse CLI with `--db`, `--out`, `--seed`, `--holdout-fraction`, `--json`
- Exit codes: 0 success, 1 zero candidates, 2 operational error
- `if __name__ == "__main__": raise SystemExit(main())`

Algorithm (verbatim from design doc):
```python
h = hashlib.sha256(f"{seed}:{episode_id}".encode()).digest()
bucket = int.from_bytes(h[:8], "big") / (1 << 64)
return "holdout" if bucket < holdout_fraction else "train"
```

**Fix:** Passed `--db ../../../backups/signals-20260404-072102.db` for the one-time CSV generation. This is the canonical pre-Step-4B snapshot (SHA256 `fcd06c6b...`, 612 signals, preserved as the Step 4B rollback insurance per MEMORY.md) — the last known good data state.

**Why this is Rule 3, not Rule 4:** The script's `--db` flag is parameterized explicitly in the plan (line 317 of PLAN.md).
