    ```powershell
    <#
    .SYNOPSIS
        Installs the Harmonic Discovery Engine daily keep-alive scheduled task.

    .DESCRIPTION
        Closes the R19 root cause by scheduling a daily local run of:
          1. python run_pipeline.py collect --collectors hacker_news,arxiv,rss_feeds,news_api
          2. python scripts/red-team-hybrid/freshness_watchdog.py --json
             (output appended to artifacts/keepalive/YYYY-MM-DD.json)

        This script must be run ONCE per machine. It is idempotent — re-running
        unregisters the previous task before re-registering, so no duplicates
        accumulate.

        Context: R19 (see docs/plans/2026-04-06-red-team-hybrid/10-risk-register.md)
        was root-caused as "no scheduled collection". LIV-01 restarted the pipeline
        once; without a scheduler, R19 recurs within 36 hours. CONTEXT.md D-22
        mandates this local installer (not a GH Actions workflow) because the CI
        DB is a separate instance from the local production signals.db per
        1-RESEARCH.md Finding 1.

    .PARAMETER TaskName
        Scheduled task name. Default: HarmonicKeepAlive.

    .PARAMETER RunAt
        Time-of-day to run the task (24h HH:MM). Default: 08:00 (local).

    .PARAMETER ProjectRoot
        Absolute path to the Harmonic repo root. Default: current directory.

    .PARAMETER PythonExe
        Path to python executable. Default: python (resolved from PATH).

    .PARAMETER TestRun
        If specified, triggers the task immediately after registering, so the
        first artifacts/keepalive/YYYY-MM-DD.json is produced without waiting
        until 08:00 tomorrow.

    .EXAMPLE
        .\install_keepalive_task.ps1
        .\install_keepalive_task.ps1 -TestRun
        .\install_keepalive_task.ps1 -RunAt "07:30" -TestRun

    .NOTES
        REQ: Phase 1 keep-alive (CONTEXT.md D-22, R19 root cause fix)
        Evidence: artifacts/keepalive/YYYY-MM-DD.json per run
        Hard rubric gate 5 requires at least 2 successful runs captured.
    #>

    [CmdletBinding()]
    param(
        [string]$TaskName = "HarmonicKeepAlive",
        [string]$RunAt = "08:00",
        [string]$ProjectRoot = (Get-Location).Path,
        [string]$PythonExe = "python",
        [switch]$TestRun
    )

    $ErrorActionPreference = "Stop"

    # Resolve absolute paths for everything
    $ProjectRoot = (Resolve-Path $ProjectRoot).Path
    $ArtifactsDir = Join-Path $ProjectRoot "artifacts\keepalive"
    if (-not (Test-Path $ArtifactsDir)) {
        New-Item -ItemType Directory -Path $ArtifactsDir -Force | Out-Null
        Write-Host "Created artifacts directory: $ArtifactsDir"
    }

    # The inner command is a one-liner PowerShell script block that runs both
    # commands sequentially. Collection runs first; freshness watchdog runs
    # regardless (even if collect errors) so we always capture a freshness
    # snapshot.
    $PipelineCmd = "$PythonExe run_pipeline.py collect --collectors hacker_news,arxiv,rss_feeds,news_api"
    $WatchdogCmd = "$PythonExe scripts/red-team-hybrid/freshness_watchdog.py --json"

    # Use cmd.exe as the shell executor so output redirection to a date-stamped
    # file is trivial. Powershell's redirection is trickier across scheduled
    # task execution contexts.
    $DailyScript = @"
    cd /d "$ProjectRoot"
    $PipelineCmd
    $WatchdogCmd > "$ArtifactsDir\%DATE:~10,4%-%DATE:~4,2%-%DATE:~7,2%.json"
    "@

    $ScriptPath = Join-Path $ProjectRoot "scripts\red-team-hybrid\_keepalive_daily.cmd"
    Set-Content -Path $ScriptPath -Value $DailyScript -Encoding ASCII

    # Build the scheduled task primitives
    $Action = New-ScheduledTaskAction -Execute "cmd.exe" `
                                      -Argument "/c `"$ScriptPath`"" `
                                      -WorkingDirectory $ProjectRoot

    $Trigger = New-ScheduledTaskTrigger -Daily -At $RunAt

    $Principal = New-ScheduledTaskPrincipal -UserId "$env:USERNAME" `
                                            -LogonType Interactive `
                                            -RunLevel Limited

    $Settings = New-ScheduledTaskSettingsSet `
                    -StartWhenAvailable `
                    -RestartCount 2 `
                    -RestartInterval (New-TimeSpan -Minutes 15) `
                    -ExecutionTimeLimit (New-TimeSpan -Hours 1) `
                    -AllowStartIfOnBatteries `
                    -DontStopIfGoingOnBatteries

    # Idempotent: remove existing task if present, then re-register
    $Existing = Get-ScheduledTask -TaskName $TaskName -ErrorAction SilentlyContinue
    if ($Existing) {
        Write-Host "Removing existing scheduled task: $TaskName"
        Unregister-ScheduledTask -TaskName $TaskName -Confirm:$false
    }

    Write-Host "Registering scheduled task: $TaskName"
    Register-ScheduledTask -TaskName $TaskName `
                           -Action $Action `
                           -Trigger $Trigger `
                           -Principal $Principal `
                           -Settings $Settings `
                           -Description "Harmonic Discovery Engine daily keep-alive (R19 root cause fix per CONTEXT.md D-22)" `
                           -Force | Out-Null

    Write-Host "Task registered. Scheduled to run daily at $RunAt local time."
    Write-Host "Evidence directory: $ArtifactsDir"
    Write-Host "Inner script: $ScriptPath"

    if ($TestRun) {
        Write-Host ""
        Write-Host "Triggering immediate test run..."
        Start-ScheduledTask -TaskName $TaskName
        Write-Host "Test run triggered. Check $ArtifactsDir in ~60 seconds for the JSON output."
    }

    Write-Host ""
    Write-Host "Next steps:"
    Write-Host "  1. Verify task exists: Get-ScheduledTask -TaskName $TaskName"
    Write-Host "  2. Verify first run: Get-ChildItem $ArtifactsDir"
    Write-Host "  3. Check exit status of last run: (Get-ScheduledTaskInfo -TaskName $TaskName).LastTaskResult"
    Write-Host "  4. Hard rubric gate 5 requires ≥2 successful runs before 2026-04-18"
    ```

    Encoding: write the file as UTF-8 (no BOM). PowerShell 5.1+ on Windows reads UTF-8 without BOM natively.

    **Important implementation notes:**
    - The `cmd.exe` wrapper is intentional because scheduled-task output-redirection is far more reliable through cmd than through powershell piped-redirection, especially across user-context and system-context execution.
    - `%DATE:~10,4%-%DATE:~4,2%-%DATE:~7,2%` is a Windows cmd batch construct for `YYYY-MM-DD` format. It depends on the machine's date format being `Day MM/DD/YYYY`. If the machine's date format is different, the script still works but the filename formatting will shift — the task owner must adjust. Document this limitation in the script comments.
    - `-Force` on Register-ScheduledTask combined with the idempotent `Unregister-ScheduledTask` above makes the installer safe to re-run.
    - The task runs as the interactive user, not SYSTEM, because the local Python env (venv, `.env` file, API keys) is scoped to the user. `LogonType Interactive` + `RunLevel Limited` keeps it from requiring admin elevation.
    - Do NOT use `New-ScheduledTaskTrigger -AtLogOn` — the task must run whether or not the user is logged in.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PowerShell script → Windows Task Scheduler | The installer registers a scheduled task with `LogonType Interactive`, `RunLevel Limited` — no SYSTEM or admin elevation. |
| Scheduled task → `run_pipeline.py` | Task invokes the project's own `run_pipeline.py`. Trust inherited from the repo. |
| Scheduled task → signals.db | Read-write to the local production DB via `run_pipeline.py collect`. This is intentional (the whole point is to keep collecting). |
| Scheduled task → artifacts/ | Writes JSON output to allowed path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | signals.db corruption via unscheduled collection | accept | `run_pipeline.py collect` is the project's own shipped entry point, already used by LIV-01. Risk is the same as any other collect invocation; WAL/SHM hardening from commit `04a5e6e` mitigates DB-level corruption. |
| T-05-02 | Supply chain | Installer executes arbitrary code | mitigate | Installer is stdlib-PowerShell only (no Install-Module). Reviewable Markdown-and-shell. `check_protected_paths.sh` confirms it lives in allowed path. |
| T-05-03 | Elevation of privilege | Installer requests admin | mitigate | `RunLevel Limited` is explicit; task does not run as SYSTEM. |
| T-05-04 | Denial of service | Runaway task floods disk | mitigate | `ExecutionTimeLimit = 1 hour`; one JSON file per day (size bounded); retention can be added in a follow-up if the cadence becomes a concern. |
| T-05-05 | Information disclosure | Sensitive data in keepalive JSON | accept | The JSON output is `freshness_watchdog.py --json`, which contains only collector names, counts, timestamps. No credentials, no PII, no raw signals. Verified from freshness_watchdog.py's `render_json()` implementation. |

<data_integrity>
signals.db is written to by the scheduled task. This is the intended behavior — keeping collection fresh IS the goal. DB corruption risk is the same as any other `run_pipeline.py collect` invocation; hardening from commit `04a5e6e` and the DBToolLock pattern apply. Read-only artifacts (keepalive JSONs) are append-only per day.
</data_integrity>
<supply_chain>
New PowerShell installer script. Stdlib-only (Register-ScheduledTask, Get-ScheduledTask, cmd.exe wrapper). No `Install-Module`, no external downloads, no network calls during install. Auditable in ~120 lines of PowerShell.
</supply_chain>
<protected_paths>

The installer's runtime invokes `run_pipeline.py` which touches `collectors/` — but `run_pipeline.py` is the shipped entry point and the runtime execution path is not a git diff, so `check_protected_paths.sh` (which diffs filesystem state) does not trip.
</protected_paths>
<secrets>
No new secrets. The scheduled task inherits the user's environment (.env file, venv, API keys) which already exist.
</secrets>
<mitigations>
- `check_protected_paths.sh` pre-commit guard
- Idempotent Unregister-then-Register pattern prevents duplicate task accumulation
- `-RunLevel Limited` prevents admin elevation
- `-ExecutionTimeLimit` caps runaway runs
- `JSON` output is schema-bounded (freshness_watchdog.py controls what's written)
- `.gitkeep` ensures the evidence directory exists even before first run
</mitigations>
</threat_model>
